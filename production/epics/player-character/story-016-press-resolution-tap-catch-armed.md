## Context

**GDD**: `design/gdd/player-character-movement.md` (P11 "Catch at press … latched at press"; P12 press, hold, channel; P10 tap/hold/channel modes); `design/gdd/input-controls.md` (R4.3 `interactResolutionOrder`, G1 latch, H-R4-2, H-R4-4, H-R4-6)
**Requirement**: `TR-movement-012` (one request at the held tick; the press → latch half), `TR-movement-011`; serves `TR-input-*` resolution order owned by input-controls (cited by acceptance ids H-R4-2/4/6)
*(Requirement text lives in `docs/architecture/tr-registry.yaml` — read fresh at review time. Acceptance ids: PCM-P11-2b, PCM-P12-1 (Tap row), H-R4-2, H-R4-4, H-R4-6.)*

**ADR Governing Implementation**: ADR-0014: Interaction framework & hold timing (§3 press resolution, the latch) — Accepted 2026-10-16 (primary); ADR-0016 (§2 `PreviewSubStep.EdgeResolve`, `IRequestSink`) and ADR-0012 (§4 `InputEdge` carries `TargetEntity`, `TargetSlot`, `PresentedSeq`) secondary — Accepted
**ADR Decision Summary**: In `EdgeResolve` (4d), after focus (4a) and the owners' previews (4b–4c), the tick's ordered `Interact` edges are applied in order (edges before hold accrual). A **press** resolves, first match wins: (1) **Catch** iff `ICatchPredictor.Evaluate` predicts a non-own flight entering this carrier's catch sphere on this tick **and** no hold is in progress **and** the flight's predicted static receiver is not the presented target anchor (D3 gate) → `Channel` start, the framework asks Throwing to send `CatchArm{down}`; (2) the **presented target's single verb** — the anchor named by the edge's presented-snapshot fields, if still registered, within `RangeMm` (the start range, not the incumbent range) and `IsAvailable` on this tick: `Tap` → build and send the request this tick; `Hold` → latch; `Channel` → start; (3) **no valid target** → catch-armed while held. A press on an unavailable target fires nothing (prompt pulse). The latch is `InteractionLatch = { AnchorRef, Verb, Mode, PressTick, HoldTicks, ClaimedPosition (feet at press), OwnerPayload (16 B) }`; a latched deliver hold is never converted into a catch.
**ADR Version**: ADR-0014 2026-10-16 + errata 2026-10-20 (own seat; §3 swim-catch owner ruling), 2026-10-21 (Panel = `CarrierStatus.PanelOpen`) and 2026-10-22 (l.66: focus at 4a); ADR-0016 2026-10-16; ADR-0012 2026-10-16

**Engine**: Godot 4.7.1 .NET (Godot-free `net8.0` Sim code) | **Risk**: LOW
**Engine Notes**: Explicit sequential layout and `byte` flags (not `bool`) in new structs (ADR-0014 engine note 2). `InteractionLatch` (`Players/InteractionLatch.cs`: `Anchor`, `Verb`, `Mode`, `PressTick`, `HoldTicks`, `Claimed`, `OwnerPayload`) and `ClaimedPosition` already exist (story 012); no new request structs here — Tap payloads are the owners'.

**Control Manifest Rules (Feature layer)**:
- Required: press resolution order Catch (`ICatchPredictor`, D3 gate) → the presented target's single verb (in `RangeMm`, `IsAvailable` now) → catch-armed (ADR-0014 §3)
- Required: edges are resolved only in `PreviewSubStep.EdgeResolve`; `InputLatch` never dispatches verbs (ADR-0016)
- Forbidden: re-targeting a hold to the current focus; timing holds on the host (ADR-0014 Alts 1, 3)

## Implementation Notes

*Derived from ADR-0014 §3 and Key Interfaces:*

- Files in `src/PerformativeMail.Sim/Players/Client/`: `EdgeResolveStep.cs` (`IClientStep`, bound at `PreviewSubStep.EdgeResolve`), `PressResolver.cs` (pure: `(edge, focusState, predictor result, registry, gate) → Resolution`), `InteractState.cs` (`Idle | Holding | Channel | ToggleArmed | Complete`, the ADR-0014 §7 name; owned here, consumed by 017/018; `ToggleArmed` is declared but never entered here — the router translates Toggle into logical press/release). `InteractionLatch` already exists in `Players/` (story 012).
- The step takes by constructor: `ICarrierFocusSource` (feet, `CarrierStatus`), `FocusStep` (its `ref FocusState`), `AnchorRegistry` (`TryGet(AnchorRef, byte contextMask, out int)`, `DefAt`, `ImplAt`, `ContextMaskAt`), `InteractionGate`, `PlayerSettings`, `IClientInputSettings` (`HoldSettingMs`), `ICatchPredictor`, `ICatchArmSender`, `IRequestSink`, the ClientLayer's `SimCounters`, and `PlayerSlot self` for `InteractionContext.Actor` (planning default D2, TD-171; story 020 wires it). `HoldSettings` comes from `HoldSettings.FromPlayerSettings`. The hooks' `InteractionContext.Tick` follows 014 (host-tick estimate, TD-170 item 4 — do not reopen); `PressTick` is `ClientStepContext.ClientTick`.
- The step publishes `InteractState`, the latch, `LastCancel` (`CancelReason`) and `LastCancelReason` (`StringId`) in a read-only state struct that Story 018 copies into the snapshot. `CancelReason` gains `Unavailable = 6` and `Busy = 7` here (append-only; story 017 appends release, range, unregistered and `ShouldCancel` after them — the `InteractionGate.cs` doc comment is updated to say so; planning default D4, TD-171).
- **Ports defined here (PROVISIONAL — shapes owned by the throwing-catching epic / ADR-0015 §8):** in `Players/` (namespace `PerformativeMail.Sim.Players`, as ADR-0014 Key Interfaces declares `ICatchPredictor`; nothing under `Sim/Throwing/`): `ICatchPredictor { CatchPrediction Evaluate(in CatchQuery q); }` with `CatchPrediction { byte Predicted; ushort FlightId; PlayerSlot Thrower; byte Units; AnchorRef PredictedStaticReceiver }` (ADR-0015 §8 return fields); `CatchQuery { uint Tick; PlayerSlot Self; Vec3Mm Chest; AnchorRef Presented }` (no ADR defines it; planning default D1, TD-171); a default `NullCatchPredictor` (never predicts); `ICatchArmSender { bool Send(bool down); }` implemented by Throwing's client code (throwing-catching 022 builds the `CatchArm{down|up}` op, ADR-0015 §7). `IRequestSink { bool TrySend(in Op op); }` is the ADR-0016 §1 port, absent on main: declare it in `Sim/ClientLayer/Ports/IRequestSink.cs` (namespace `PerformativeMail.Sim.ClientLayer`); tests use an in-memory fake. Network-adapter-loopback 006 shipped `ClientAdapter.TrySend(OpKind, ReadOnlySpan<byte>, out ushort)` but no `IRequestSink`; the production adapter over it and `ClientLayer.Attach(in ClientPorts)` are godot-host-shell 005's, not this story's.
- The presented target comes from the `InputEdge` fields `(TargetEntity` uint, `TargetSlot` byte, `PresentedSeq` ushort`)` (ADR-0012 §4; `ClientLayer/InputEdge.cs`), converted as `new AnchorRef(new EntityId(edge.TargetEntity), edge.TargetSlot)`; `TargetEntity == 0` means no presented target. `PresentedSeq` is for the router/snapshot bookkeeping (Story 018); resolution uses `(TargetEntity, TargetSlot)` only.
- D3 gate: `catch = predictor.Predicted ∧ ¬holdInProgress ∧ predictor.PredictedStaticReceiver ≠ presentedAnchor`. No off-hysteresis preemption.
- `ctx.Tick` is the client tick (`ClientStepContext.ClientTick`, sim-core story 023); `PressTick` is that tick, which is also the tick the router attached the edge to (first tick of a catch-up batch).
- The hook calls use only `in`/value params; the `PureHookGuard` test decorator (today a private nested class in `tests/unit/player/AnchorRegistryTests.cs`) is lifted into `tests/unit/player/PlayersTestKit.cs` and wraps test owners.
- The former "unregistered / out of range" ambiguity is settled by ADR-0014 l.78–81 and input-controls l.108 ("no valid target"): see the Start range and Unavailable ACs.
- **Mail Lead planning defaults, pending Evan (TD-171; not rulings, none contradicts an Accepted ADR):** D1 `CatchQuery`'s fields; D2 the `PlayerSlot self` constructor argument; D3 `IsAvailable` is the only press refusal (`OnPress` cannot refuse — `IInteractable.OnPress` returns void per ADR-0014 l.146; manual-delivery 004 l.48 has `OnPress` "refuse if `!CanStartHoldNext`" (`deliver.cancel.settle`) — that refusal must move to `IsAvailable` (MD 003) when 004 is readied); D4 `CancelReason.Unavailable = 6` / `Busy = 7` appended here, 017 appends the rest; D5 `CounterId.InteractPressIgnored = 54`; D6 Dead / Panel / Mounted-without-own-seat refuse the edge entirely (no `CatchArm`).
