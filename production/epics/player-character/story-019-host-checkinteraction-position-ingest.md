Phase 3 (`PlayersStep`, host role) ingests the T−1 sample latch and runs the host-role solver only for host-authored (Dead / Frozen) bodies.

## Acceptance Criteria

*From GDD `design/gdd/player-character-movement.md` (PCM-P13-1, PCM-F5-1, PCM-P2-2), scoped to **M-1a**. Deferred to M0 (ADR-0020, no story this epic): the 9+3-tick position-history ring, dead-reckoning corroboration, `Teleport` history clearing and `seq` discard — see Implementation Notes. The GDD's "Deliver accepts at 3500 (per-verb r = 3000)" row is superseded by ADR-0014 §5 (single `RangeMm`).*

- [x] **PCM-P13-1 (parametrised).** a request failing two checks reports the **first** in `dead → frozen → no_target → unavailable → out_of_range / position_stale` (e.g. Dead + unknown anchor → `Dead`; Frozen + unavailable → `Frozen`; unknown anchor + out of range → `NoTarget`; unavailable + stale → `Unavailable`); `CheckInteraction` is read-only — no `TickGuard.IsMutable` call (`src/PerformativeMail.Sim/Core/TickGuard.cs:25`; `TickGuard.AssertMutable` does not exist) — legal in phases 0–12 and between ticks, mutates nothing and raises no event (a test snapshots the Players dump hash before/after, calling it between ticks); the reply routing "to the requester only" is the op layer's.
- [x] **PCM-F5-1 (M-1a rows).** Open/Pickup-style anchor `RangeMm` 2500: a claim whose chest point is 3000 mm from the anchor point **accepts** (`2500 + rangeSlackMm 500`), 3001 → `OutOfRange`; the claim within `claimToleranceMm` (1500 mm, 3D) of the player's newest ingested sample accepts, 1501 → `OutOfRange`; an anchor 2000 mm above the feet at a 2500 mm client chest distance accepts (3D distance, chest = claim + `(0, chestMm, 0)`); a Deliver anchor (`RangeMm` 2500) accepts at 3000 and rejects at 3001; **30 silent ticks** still pass, **31** → `PositionStale` (and open panels are kept — the leash below never fires on a stale position).
- [x] **Leash query.** `IPlayersApi.LeashExceeded(PlayerSlot, in Vec3Mm anchorPoint, int leashMm)` is true iff the position is **not stale** and `|chest(newest) − anchor| > leashMm` (strict): false at exactly 3000 mm, true at 3001; always false when the position is stale (no transform for > `positionStaleTicks`); Grid Inventory story 019's H-R10-1 leash clauses (2.99 m stays open, 3.01 m closes, stale never closes) pass against it.
- [x] **Seeding (`PC019-SEED-1`).** `PlayerJoin` seeds `HostPositionTable[slot]` from the pad position with `LastReceivedTick = join tick` (Story 001's `PlayerRecord` has no position slot or `LastReceivedTick`; `OnPlayerJoined` seeds `Carrier.X/Y/Z` only, `src/PerformativeMail.Sim/Players/PlayersSystem.cs:175-188`), so an `Open` at the spawn point on the next tick passes (no `position_stale` right after joining); negative case: 31 silent ticks after the join → `PositionStale`.
- [x] **PCM-P2-2.** `PlayersStep` (phase 3) ingests the tick's latched `TransformSample`s in slot order then sequence order for **Alive** players: the newest becomes the stored host position (feet X, Y, Z; yaw; the swimming bit `SampleFlags.Swimming = 1` of `TransformSample.Flags` — layout fixed by this story, see Implementation Notes), `LastReceivedTick` = `ISampleLatch.ReceivedTick` (the stamp is per latch, `src/PerformativeMail.Sim/Core/ISampleLatch.cs:23`; `TransformSample` has no per-sample field, `Core/TransformSample.cs:23-53`); over 100 ticks of an Alive remote player's reports the host calls `OwnedCarrier.Step` **zero times** for it (`CounterId.HostCarrierSteps = 61` stays 0 — `OwnedCarrier.Step` is static, `Players/OwnedCarrier.cs:19`, so a real counter replaces the spy; TD-188 item 6) and `SamplesIngested = 62` counts each ingested sample; for a body whose life state is **Dead or Frozen** (set directly by the test fixture through the internal `RecordRef` — `rig.Record(slot).Life = LifeState.Dead`, `PlayersSystem.cs:149`, `tests/unit/player/PlayersTestKit.cs:70`, because `LifeStates.CanTransition` admits only Joining → Alive, `Players/LifeState.cs:41`; knockdown/disconnect are M-1b/M0) the host authors the transform with `HostAuthored` input, after the step the body's feet Y equals the terrain height under (X, Z), and the owner's samples are **ignored** (`SamplesIgnoredAuthored = 63` counts them).
- [x] **Unavailable on host state (`PC019-UNAV-1`).** The framework gate runs first, then the owner's `IsAvailable` (TD-188 item 4): the gate's swimming reason (`dry_land`) applies when the stored sample's `SampleFlags.Swimming` bit is set and the anchor lacks `AllowWhileSwimming` (test: bit 0 set → stored swimming → `Unavailable(dry_land)`); otherwise `Unavailable(reasonKey)` comes from `IInteractable.IsAvailable` evaluated with the host-side `InteractionContext` (host state, TD-188 item 3); Panel is client-only and never evaluated on the host (`PanelOpen = false`, `OccupiedSeat = None` in the host-built `CarrierStatus`).
- [x] **Counters / budget.** `CheckInteraction` is allocation-free and O(1) beyond the registry's existing linear `AnchorRegistry.TryGet` (`src/PerformativeMail.Sim/Players/AnchorRegistry.cs:233-246`, a scan over the high-water mark bounded by `player.maxAnchors`; an `AnchorRef → index` map is optional follow-up debt); `CounterId.HostCarrierSteps = 61`, `SamplesIngested = 62`, `SamplesIgnoredAuthored = 63` are real counters (TD-188 item 6; asserted through `PlayersStepTests`; the `SimCounters` length pin was deleted under lean-testing (`.claude/rules/lean-testing.md`), PR #64); `PlayersStep` for 8 players with 2 000 registered anchors (none stepped) stays within a recorded, advisory `players.hostStep` budget (≤ 0.20 ms p99 target; **logged only** — TR-movement-021 has no ADR coverage; the Stopwatch ban RS0030 applies to the Sim assembly, `tests/fixtures/analyzers/BanStopwatch.cs`, so the measurement lives in the test); the 0 B half runs through `tests/PerformativeMail.Sim.Tests/AllocAssert.cs` and is **advisory until M0** (E2).
