## Context

**GDD**: `design/gdd/content-data-definitions.md` (CD21 the Godot-side `ContentHost` reads `manifest.txt` and each listed file as bytes and hands them to the Sim's `ContentLoader` through `IContentSource`; CDD-LOAD-2/-3 error behaviour; the `ContentHostState` table)
**Requirement**: `TR-content-021` (loader reads via `IContentSource`; the Sim never reads `res://`), `TR-content-028` (boot parse + validate + hash ≤ 100 ms CPU — the synchronous-load budget; advisory, measured and logged)
*(Requirement text lives in `docs/architecture/tr-registry.yaml` — read fresh at review time. The M-1a default remains `BuiltInContent`; `ContentHost` is built now but is **not** the default source — ADR-0019's Ordering Note schedules it for M0, the epic pulls the minimal class into M-1a; the `ContentHostState` surface and the opt-in mode have no extra TR-ID.)*

**ADR Governing Implementation**: ADR-0019: Godot Presentation Scene Architecture (§4 `ContentHost`: a plain C# class implementing `IContentSource`, not a Node and not an autoload; synchronous; `ContentHostState`; `FileAccess.GetFileAsBytes` + `GetOpenError()` on every read; never `GetAsText`; never `DirAccess` enumeration of the PCK) — Accepted 2026-10-16 (primary); ADR-0010 (§1 `IContentSource` is the only file seam, the manifest is mandatory; §4 five-stage loader into one `ContentSet`) — Accepted 2026-10-16 (secondary)
**ADR Decision Summary**: `src/Game/Content/ContentHost.cs` implements `IContentSource.ListManifest()` (reads `res://content/manifest.txt`) and `Read(path)` (`FileAccess.GetFileAsBytes("res://content/" + path)`, error from `GetOpenError()` becomes a loader error carrying the path); the shipped `IContentSource` read is `bool TryRead(path, out bytes)`, false for a missing file, and `ContentHost` will implement `TryRead` (ADR-0010/ADR-0019 notes 2026-11-01, no design change). It exposes `ContentHostState { Unloaded, Loading, Valid, Failed, Reloading }`. Loading is synchronous at boot, with no threads and no `CallDeferred`. The `EmbeddedResource` fallback stays behind the same interface for use only if the first export story (V1) shows the C# PCK read fails. F6 hot reload and `DirectorySource` selection are M0.
**ADR Version**: ADR-0019 2026-10-16; ADR-0010 2026-10-16

**Engine**: Godot 4.7.1 .NET | **Risk**: HIGH
**Engine Notes**: `FileAccess.GetFileAsBytes` + `GetOpenError()` are the 4.6-safe path (4.6 removed `get_as_text(skip_cr)`; manifest forbids `GetAsText`). Reading `res://content/*` from an **exported** PCK via C# is UNVERIFIED (spike S1-5: a C# read under the editor binary's `--main-pack` fails — no assembly in the pack; a GDScript read passes) — ADR-0019 V1, owned by the export story; this story is editor/headless-only. `*.jsonc` and `manifest.txt` are packed only through `include_filter` (S1-2) — export presets are out of scope here. `content/` must never carry a `.gdignore` (it would beat `include_filter`).

**Control Manifest Rules (Foundation / Presentation)**:
- Required: `ContentHost` is a plain synchronous class: `FileAccess.GetFileAsBytes` + `GetOpenError()` on every call; the loader reads only through `IContentSource` (ADR-0019, ADR-0010 §1); `content/manifest.txt` is generated by `ContentValidator --write-manifest` at export and never committed (ADR-0010 §1)
- Forbidden: `FileAccess.get_as_text`/`GetAsText`; `DirAccess` enumeration of the PCK; threads or `CallDeferred` for loading; a static/autoload `ContentHost`; the Sim reading `res://`
- Guardrail: content load advisory ≤ 100 ms CPU (TR-content-028) — logged

## Acceptance Criteria

*From ADR-0019 §4 and CDD-LOAD-2/-3 (host half), scoped to this story. Delta: the repo root already holds `content/` (eleven JSONC files under `content/balance`, `content/items` and `content/mail`; `project.godot` is at the repo root, so `res://content/` resolves) but no `content/manifest.txt` (generated by `ContentValidator --write-manifest` at M0), so M-1a boot still uses `BuiltInContent` and AC 3's failure arm holds (readiness correction 2026-11-01 — the old sentence said no `content/` directory exists); the Sim half (`IContentSource`, `DirectorySource`, `InMemorySource`, `ContentLoader`) comes from content-data 017–019.*

- [ ] **`ContentHost` reads bytes through `FileAccess`.** `ContentHost(string rootPath = "res://content")` implements the shipped `IContentSource` (`src/PerformativeMail.Sim/Content/Sources/IContentSource.cs`; ADR-0010 l.62/l.125 and ADR-0019 l.135/l.247 notes, approved by Evan 2026-11-01 10:11 AM PT (card t217s1032) and, as now worded, 12:05 PM PT (card t222s1054), both by card click) and reads content through `TryRead` (Mail Lead planning default, approved by Evan 2026-11-01 12:05 PM PT by card click (TD-204 item 4)): `ImmutableArray<string> ListManifest()` returns the lines of `<root>/manifest.txt` (read as bytes, decoded as UTF-8, CRLF/LF tolerant, blank lines skipped; ordering preserved — the manifest is already ordinal-sorted by its generator) and `bool TryRead(string path, out ReadOnlyMemory<byte> bytes)` returns true with the file's bytes. A path that is not in the pack returns false from `TryRead`. Any other open error raises `ContentHostReadException` with the path and the error code, so an empty buffer is never returned silently. Every open checks `FileAccess.GetOpenError()`. A smoke scenario points a `ContentHost` at `res://` and reads `project.godot` (a file that always exists in an editor/headless run) through `TryRead`: true, non-empty, starts with `; Engine configuration file`, byte-identical to `System.IO.File.ReadAllBytes` of the same file, and the open error was checked (instrumented seam). `TryRead("does_not_exist.bin")` on a `ContentHost` rooted at `res://` returns false with empty bytes and raises nothing. A grep guard asserts `GetAsText`, `GetFileAsString` and `DirAccess` appear nowhere under `src/Game/Content/`.
- [ ] **State table.** `ContentHostState` is `Unloaded → Loading → Valid | Failed` for a load (and `Reloading` reserved for M0's F6): `Load()` sets `Loading`, runs `ContentLoader.Load(this)` (content-data 019) synchronously on the calling (main) thread, and ends `Valid` with the one `ContentSet`, or `Failed` with the full diagnostic list preserved; `Load` while `Valid` is refused (no re-parse, CDD-LOAD-4 shape). The wall time of the load is measured with `Stopwatch` and logged against the 100 ms advisory budget.
- [ ] **Opt-in host content mode, default unchanged.** `--content=host` (user args) or env `PM_CONTENT=host` makes boot step 2 use `ContentHost` + `ContentLoader.Load` instead of `BuiltInContent` through story 004's `IContentBootSource`; the default stays `BuiltInContent.CreateM1a()`. With `--content=host` and no `res://content/manifest.txt` (the repo today), boot step 2 ends `FAIL`, `ContentHost.State == Failed`, the error screen (story 004) lists the missing manifest path, the Sim is never composed and the smoke exits `4` — that failure path is the testable M-1a behaviour; the success path uses a fixture under `user://content-host-fixture/`; its state machine (`Unloaded`, `Loading`, `Valid`, `Failed`) is tested without Godot if a Godot-driven run can't reach `Valid` (Mail Lead planning default, approved by Evan 2026-11-01 12:05 PM PT by card click (TD-204 item 5)) (the loader's own acceptance of real JSONC is content-data 019's and M0's `BuiltInContent ≡ JSONC` equality test, not this story's).

## Implementation Notes

*Derived from ADR-0019 §4, ADR-0010 §1/§4:*

- Files in `src/Game/Content/`: `ContentHost.cs`, `ContentHostState.cs`, `ContentHostReadException.cs`, `HostContentBootSource.cs` (implements story 004's `IContentBootSource`). `ContentHost` is constructed by the boot step, never discovered; it is not a `Node`.
- **Grep guard mechanism** (Mail Lead planning default, approved by Evan 2026-11-01 12:05 PM PT by card click (TD-204 item 6)): AC 1's `GetAsText`/`GetFileAsString`/`DirAccess` ban runs as a rule in `tools/ci/check-scene-rules.sh`. (Repo convention, not part of the ruling: that script's rules are R1–R9 today, each with a planted violation in its `--self-check`.)
- **Failed load at boot** (Mail Lead planning default, approved by Evan 2026-11-01 12:05 PM PT by card click (TD-204 item 7)): a failed host load at boot throws and shows the error screen, no fallback. (How the shipped boot code does that: `IContentBootSource.Load` returns a non-null `ContentSet` and `ContentSourceStep` turns any throw into the content error screen with the Sim never composed, `src/Game/Boot/IContentBootSource.cs:8`, `src/Game/Boot/ContentSourceStep.cs:10-11, 33-34`; so `HostContentBootSource.Load` throws when the host ends `Failed`, and AC 3's error screen lists the missing manifest path.)
- The `manifest.txt` generator (`ContentValidator --write-manifest`, `tools/ContentValidator`) is M0; `DirectorySource` enumerates and ordinal-sorts itself (ADR-0010). The host's `ListManifest` therefore trusts the file's order and does not sort.
- Do **not** add `EmbeddedResource` packaging now; keep the fallback as an unimplemented note until V1 shows it is needed.
- `ContentLoader.Load` and `ContentLoadResult` shapes come from content-data 019; adapt to its actual API and record deviations. If `ContentLoader` is not yet merged when this story runs, build the class and the smoke against `IContentSource` only and leave the `Load` AC rows (state table) to a re-run — do not mark that AC passed.
- F6 hot reload (`Debug/ContentReloadKey`, `--content-dir`, `PM_CONTENT_DIR`) is M0 (TR-content-026) and is **not** built here.
